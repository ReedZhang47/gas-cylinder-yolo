   - 备选：Computer-Aided Civil and Infrastructure Engineering（Wiley，一区 Top）。
2. **落点候选**（二区开源 OA）：
   - **Sensors**（MDPI）：快（首决数周）、模板化、工程 CV 常见落点；
   - **Buildings**（MDPI）：建筑工程 scope 最贴合；

   - ⚠️ 投前必做：核对**最新中科院分区表**（分区逐年变动，以上为写作时认知）+ **国际期刊预警名单** + 官网 "submission to first decision" 中位周期；确认 APC（约 2000~3000 CHF/USD 级）预算。

## 二、篇章结构与篇幅

3. **Methodology**——3.1 问题与类别定义（监理口径：放置问题=未固定，含倒地）；3.2 真实种子数据（93 张人工标注、v2 分层划分 60/33、正/负样本设计）；3.3 生成管线（z-image-turbo 文生图、qwen-image-edit 编辑真实照片、canny ControlNet 试验；真实性红线：脏污/磨损，防"过净"域差）；3.4 自动预打标 + 人工复核闭环（labeler 模型 + annotator GUI）；3.5 评测协议（真实集 v2 划分、**test33 不训练不选权**的红线、全量口径 vs test33 干净口径的泄露分析、全篇固定 100 轮报 last.pt）。
4. **Experiments**——4.1 setup（6 权重 × 统一超参、硬件）；4.2 labeler 基线与泄露分析（93 全量 vs test33 双口径；含「训练预算放大污染虚高」证据——同一真实臂 100 vs 300 轮：污染口径 +0.11~+0.33、干净口径 ±0.02，见 `phase7_300ep_check.json`）；4.3 主结果：生成数据增益（gen493 复核修订版六权重全表；v1 口径下两轮 6/6 全胜，v2 切换后按 last.pt + test33 重算）；4.4 **数据规模消融**【待实验】；4.5 推理分辨率分析（imgsz 扫描；真实照片 17% 小目标在 640 下被压没的发现）；4.6 **跨目标扩展（安全帽）**【待实验】；4.7 **基线对照**【经典增广三臂 v2：设计已定（第四节 3），待跑】。

## 四、投稿前必须补的实验（按优先级）

> 完整清单（含每项的可开始状态、建议新增实验、共享 GPU 窗口的排期）见仓库根 `List_of_Experiments.md`（2026-09-17 立）；本节只保留设计要点。

1. **250 vs 493 减半对比**（现批次减半；最佳权重或 s 家族 2~3 个，GPU 1~2 h）——量-效曲线第一个点，最便宜、最能支撑"数量取胜"；评测用 v2 口径（test93 全量 + test33 干净）。
2. **累计扩量重训**【⚠️ 2026-09-18 作废重做】——原 1085 张的划分+训练+评测已完成，但审计发现生成图是真实照片的编辑版、训练池含 test33 的编辑版 → 结果作废。重做需先过 `scripts\make_gen_clean.py` 过滤；池规模取决于路线（A：gen_clean 474 张；B：另收从未用作编辑源的真实照片做新 test，则 1085 张可全用）。**注意**：这也意味着论文的 Methodology 要改写——管线是「编辑真实照片合成违规状态」而非文生图，多样性上界 = 源照片数量。
3. **经典增广对照：离线增广补量**【2026-09-17 升级为 v2 口径：真实集 60/33 重划 + 600/600 同量级 + 固定轮数协议；方案 A 已批准】——回答"为什么生成式扩量，而不是免费的传统增广"。三臂只差训练数据来源，同超参、同 test、同训练轮数（三臂均带 ultralytics 默认在线增强 mosaic/HSV/fliplr）：

   | 臂 | 训练数据 | 状态 |
   |---|---|---|
   | A 真实基线 | **60 张真实（v2 train60）** | ✅ 已有（`runs\detect\real60\`，2026-09-18；同时就是主表的新真实基线） |
   | B 真实+离线增广 | 60 张 ×10 → **600 张**（370 正 + 230 负） | 待跑（新增） |
   | C 生成数据 | **600 张生成图**（从 1085 池按 370 正 + 230 负 同比例抽样，固定 seed） | 待跑（新增；与 gen493 主表是两回事） |

   - **真实集 v2 划分（前置，先执行）**：93 张 → train 60（37 正 + 23 负）/ test 33（20 正 + 13 负），按正/负分层、seed 固定；脚本 `scripts\splits_real_v2\make_split_real_v2.py`，输出 `D:\gas_cylinders\real_photo\93_real_photos\v2_split\`（含训练/评测用 data.yaml，全部绝对路径）。**test33（33 图/约 60 框）取代 v1 的 val18（18 图/30 框）成为唯一干净口径**——33 张只评测，任何模型不训练、不选权、不碰；v1_split 保留。
   - **选权协议（全篇统一）**：固定 100 epoch / imgsz 640 / batch 16，**报最后一轮（last.pt），不做验证集选权**。理由：重划后真实臂没有真实验证集可用，而生成臂有 gen-val——统一"固定轮数、不选权"是对三臂最对称的规则；主表 gen 权重按 last.pt 重评（分钟级，不用重训），实测 best vs last 差 ≤0.02、同规则比较结论不变。
   - 增广类型：水平翻转、±10° 旋转、缩放/平移、亮度/对比度/HSV 抖动（几何变换同步变换框；正/负样本比例保持）。**不用上下翻转**（工地实景有重力方向，上下翻转物理上不成立，易被审稿人质疑）。
   - 实现：增广脚本 `scripts\splits_aug60\make_aug60_dataset.py` → 数据区 `real_photo\aug60_train\`（600 张）；C 臂抽样脚本（1085 池 → 600，固定 seed）。依赖优先零新增（cv2/PIL 自实现，环境自带）。
   - **解读预案**（先说好三种结果的写法）：C > B > A → 坐实"同量级下生成优于传统增广"；B ≈ C → 口径改为"传统增广能补量、补不了多样性"（需补多样性辅助论证：B 的 600 张仍只有 60 个场景/背景）；B 明显低于 C → 最常见、故事最顺。
   - 机制句（写进论文）：传统增广不增加场景/背景多样性，生成数据增加的是"新场景"——两者本质差异，也是 B 臂的天花板。
   - 统计：test33 仍偏小（约 60 框），对比结论建议附 bootstrap 置信区间或逐图 AP 离散度；三臂可先跑六权重（≈3 h GPU），必要时给 s 家族补随机种子。
   - 排期：真实集 v2 重划 → 1085 重训 → 三臂与减半对比共用同一 GPU 窗口串行跑齐（见 `List_of_Experiments.md` 第四节）。
4. **安全帽第二目标**（生成 200~500 张 + 复核 + 训练；`Hardhat\` 素材已起步，2 张真实图）——跨目标证据，支撑方法通用性；样本到手后的实验设计（含跨目标迁移、双目标统一模型）见 `List_of_Experiments.md` 第三节。
5. （可选，应对审稿人必然之问）**混合训练口径**：493 生成 + 60 真实（v2 train60）混合训练，test 仍用 v2 test33（与 train60 不相交，保持干净）——回答"为什么不混真实数据"。

## 五、立论口径（红线）

- 主张 **methodology + empirical evidence**，不主张"合成数据优于真实"；"数量取胜"必须先有第四节 1/2 的实验支撑才可写进 contributions。
- **三级定位**（与路线图第 5 步口径一致）：
  1. **Application paper**（单目标，第四节 1/3/4 完成即可成文首投）；
  2. **Method paper**（加安全帽跨目标证据 → "可推广到其它稀缺目标的增广管线"，素材全复用）；
  3. **通用数据增广协议**（"各行各业数据稀缺都适用"——升格为正式贡献需要**第二个非工地域**的证据；当前只作 Discussion 愿景与 future work，避免审稿人攻击 overclaim）。
- 建议路径：首投版按 Application 写；等待首投结果期间跑第四节 2/5；转投升级视第二目标完成度决定。
- 通用性主张靠"跨行业数据稀缺"的动机论述（Introduction/Discussion）+ 跨目标证据（4.6）两头支撑，不靠行业内单一数据集硬撑。
- 合成数据按各刊 **AI 使用披露政策**写明生成工具/模型/版本并引用官方论文（qwen-image-edit 授权已确认，仅需引用论文）。
